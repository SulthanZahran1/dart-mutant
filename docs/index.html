Why mutation testing?

Code coverage tells you what code runs during tests. Mutation testing tells you what your tests actually verify. A line can be 100% covered and still harbor a bug your tests would never catch. dart_mutant systematically injects small, deliberate faults (mutants) and runs your tests against each one — a mutant that survives is a test gap.

Quick start

cd my-dart-project
dart_mutant                          # auto-detect, run everything
dart_mutant --threshold 80           # CI gate: exit 0 if MSI ≥ 80
dart_mutant --format json --quiet    # pure JSON for CI dashboards & AI agents
dart_mutant --detect-equivalent      # TCE equivalent-mutant detection
dart_mutant --mutant 42              # re-run one mutant after writing a killing test

Performance engineering

  • Coverage routing — only test files covering the mutated line run per mutant
  • Schemata — mutations injected via DART_MUTANT_ID env switch, compile once
  • Parallel — Rayon across CPU cores, per-file grouping avoids contention
  • Adaptive timeout — baseline duration × 3, bounded 5s–5min
  • Incremental cache — SHA-256 content-addressed, warm reruns in seconds

Reports
