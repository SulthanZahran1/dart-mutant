# dart_mutant CLI / JSON Contract

_Frozen: 2026-08-02. Schema version 1.0._

This document defines the **frozen contract** that AI agents and CI systems rely
on when they shell out to `dart_mutant`. Anything listed here is stable: it will
not change in a breaking way without a major version bump (e.g. `1.0` → `2.0`).

## CLI flags

These flags and their semantics are frozen. New flags may be added (additive
only); existing flags keep their current names, types, and exit behavior.

| Flag | Type | Default | Description |
|---|---|---|---|
| `--path` | path | current dir | Path to the Dart/Flutter project to mutate. |
| `--threshold` | f64 | 0 | MSI threshold for the CI gate (0–100). Exit 1 if below. |
| `--format` | list | `console` | Output formats, comma-separated: `console,html,json,junit`. |
| `--quiet` | flag | false | Suppress progress output; emit JSON only when `--format json`. |
| `--no-color` | flag | false | Disable ANSI color codes in console output. |
| `--mutant` | id | — | Run a single mutant by ID (for iterative fixing). |
| `--parallel` | usize | CPU count | Parallel workers for mutant execution. |
| `--sample` | usize | — | Limit mutations to the first N (quick feedback). |
| `--incremental` | flag | false | Only mutate files changed vs `--base-ref`. |
| `--base-ref` | git ref | `main` | Git ref for incremental mode (`git diff`). |
| `--detect-equivalent` | flag | false | Enable TCE equivalent-mutant detection. |
| `--exclude` | list | — | Exclude glob patterns (e.g. `*.g.dart,lib/generated/**`). |

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Pass — mutation score ≥ threshold. |
| `1` | Below threshold — mutation score < threshold. |
| `2` | Error — pipeline failure (no source files, compile error, etc.). |

## Agent JSON output (`--format json`)

When `--format json` (commonly with `--quiet --no-color`) is used, a single JSON
object is printed to **stdout**. This is the agent-facing schema:

- **Field naming**: all multi-word fields are **camelCase** (e.g.
  `mutationScore`, `notCovered`, `compileError`).
- **`schemaVersion`**: `"1.0"` — always the **first** key. Bumped only on a
  breaking change to this contract.

### Top-level fields

| Field | Type | Description |
|---|---|---|
| `schemaVersion` | string | Schema version, frozen at `"1.0"`. |
| `mutationScore` | f64 | Mutation Score Index (MSI), 0–100. |
| `mutationCoverage` | f64 | Mutation coverage, 0–100. |
| `total` | usize | Total mutants discovered. |
| `killed` | usize | Mutants killed by tests. |
| `survived` | usize | Mutants that survived (test gap). |
| `timeout` | usize | Mutants that timed out. |
| `equivalent` | usize | Mutants detected as equivalent (TCE). |
| `notCovered` | usize | Mutants with no covering tests. |
| `compileError` | usize | Mutants that failed to compile. |
| `threshold` | f64 | The `--threshold` value used (0–100). |
| `passed` | bool | `true` if `mutationScore >= threshold`. |
| `files` | array | Per-file breakdown (see below). |

### `files[]` entries

| Field | Type | Description |
|---|---|---|
| `path` | string | Source file path (relative to project root). |
| `mutationScore` | f64 | Per-file mutation score, 0–100. |
| `killed` | usize | Killed mutants in this file. |
| `survived` | usize | Survived mutants in this file. |
| `total` | usize | Total mutants in this file. |

### Example

```json
{
  "schemaVersion": "1.0",
  "mutationScore": 72.5,
  "mutationCoverage": 85.0,
  "total": 500,
  "killed": 310,
  "survived": 118,
  "timeout": 12,
  "equivalent": 30,
  "notCovered": 25,
  "compileError": 5,
  "threshold": 80,
  "passed": false,
  "files": [
    {
      "path": "lib/src/math_utils.dart",
      "mutationScore": 90.0,
      "killed": 18,
      "survived": 2,
      "total": 20
    }
  ]
}
```

## Freeze rule

This contract is **additive-only** under schema version `1.0`:

- **Allowed** without bumping: adding new optional fields to the JSON object,
  adding new CLI flags, adding new `--format` values. Existing consumers that
  ignore unknown keys continue to work.
- **Breaking changes** — removing/renaming a field, changing a field's type,
  changing an exit code, reordering existing fields, removing `schemaVersion`
  as the first key — require bumping `schemaVersion` to a new major version
  (e.g. `2.0`) and documenting the migration.

The Stryker-format report written to `mutation-reports/mutation-report.json`
is a **separate** schema (`schemaVersion: "2"`, the mutation-testing-elements
standard) and is **not** part of this contract. It is generated by
`dart-mutant-report` and may follow the upstream Stryker schema independently.
